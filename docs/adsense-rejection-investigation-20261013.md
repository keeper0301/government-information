10월 12일 메일은 광고 게재 불승인을 통지했지만 구체 사유는 적지 않았다. 조사 브라우저는 Google 로그인 화면으로 연결돼 AdSense Sites 상세 사유를 읽지 못했다. news 67.2%를 Google의 실제 반려 사유로 확정하지 않는다. 낮은 가치 콘텐츠, 사이트 접근 문제, 정책 위반 중 어느 항목인지도 현재 미확인이다.

Google의 승인 여부, 내부 준비 지표, 공개 페이지의 품질 검증은 각각 별도 판단이다. 60%와 백필 80%는 keepioo 내부 기준이며 Google 승인 기준이 아니다.

## 확인한 코드 결함과 수정

1. 운영 master는 백필 ≥80%만 확인하고 news 비중을 전환 POST에서 확인하지 않는다. PR #365의 공통 임계치를 유지해 알림·대시보드·GET·POST를 일치시켰다.
2. 기존 백필 분자·분모 쿼리가 동일했다. 뉴스가 있으면 100%로 계산된다. `summary + classified_at`를 갖춘 비-press 뉴스 중 해설이 있는 비율로 수정했다. index 가능 news 비중의 기존 분모는 유지했다.
3. Supabase 오류 및 null count를 0건으로 치환했다. 전환 API는 미확인 통계에 503으로 차단한다. 모니터링은 unknown 신호와 경고를 남기고 다른 운영 점검을 이어간다.
4. 내부 수치만으로 Google 승인으로 오인할 수 있었다. keepioo.com Sites 상태를 운영자가 직접 확인했다는 체크가 있어야 POST가 진행되게 했다. 이는 운영자 확인 기록이며 Google API가 검증한 승인 증거가 아니다. 기존 인증은 유지했다.
5. 진단 도구가 현재 `발행·확인일` 문구, React로 분리된 뉴스 건수, 검수 기록에 포함된 추가 복지로 공식 출처를 인식하지 못했다. 정확한 문구·출처 검증을 유지하며 오탐을 보완했다. 광고·색인 조건은 이 진단 수정으로 완화하지 않았다.

## 콘텐츠와 공개 표면 점검

- live 준비 점검: 사이트맵에서 찾은 가이드 8개 모두 직접 공식 출처·검수 기록·색인 설정·본문 존재 점검 통과. 글의 실제 정확성 전체나 Google 승인까지 증명하는 검사는 아니다.
- 공개 20개 경로 수집 완료. 초기 1건은 월세 가이드의 추가 복지로 공식 공지를 오래된 기대 출처 목록이 거부한 오탐이다. 보관한 실제 HTML을 수정된 진단으로 재분석해 확인했다.
- 초기 preflight는 21건 실패를 보고했다. 새 발행·확인 문구 및 목록 공백을 인식하지 못하는 진단 문제를 확인했다. 실패 수를 곧바로 실제 미검수 글 수로 해석하지 않았다.
- review mode에서도 `editorial_news_publications`의 자동 근거 검사 통과 뉴스는 공개·사이트맵에 들어간다. `news_posts` 38,961건이라는 내부 수치가 현재 공개 또는 사이트맵 뉴스 수를 뜻하지 않는다.
- 자동 뉴스는 사람 검수와 다른 경로다. 실제 반려 사유가 콘텐츠 가치라면 공개 자동뉴스 표본의 원문 의존도·추가 설명 가치·중복·내용 최신성을 별도로 판단해야 한다. 개수 채우기, 임의 백필, 사람 승인 기록 생성은 하지 않았다.

## 재심사 전 순서

1. AdSense Sites → keepioo.com의 정확한 반려 문구와 확인 시각을 확보한다.
2. PR #365 보완의 병합·배포 후 운영 GET에 비율·미확인 통계 차단이 반영됐는지 read-only로 확인한다. 광고 모드는 유지한다.
3. 왜곡됐던 백필 지표를 새 식으로 다시 측정한다. news 60% 미만을 맞추려고 임의 삭제하거나 지표만 낮추지 않는다.
4. 실제 반려 항목에 맞춰 공개 콘텐츠 또는 연결·크롤링 문제를 수정한다. 자동 뉴스와 사람 검수 글을 구분해 확인한다.
5. 정확한 문제 해결과 공개 페이지 검증 뒤 재심사는 한 번 요청한다. 현재는 요청하지 않는다. Google 승인 후에도 광고는 페이지별 검수 조건을 충족해야 한다.
