# 정책 원문과 설명 검수

정책 상세의 자체 설명은 원문에 있는 근거를 대조한 뒤 운영자가 승인해야 공개됩니다. 수집 주소를 복구하는 작업과 설명을 승인하는 작업은 별개입니다.

## 검수 화면 사용

1. 관리자 로그인 후 메뉴의 정책 원문 검수 화면을 엽니다.
2. 복지 또는 금융 종류를 선택하고 검수 목록에서 정책 제목을 누릅니다. 제목 검색과 정책 번호 직접 입력도 사용할 수 있습니다.
3. 수집 출처가 해당 사업·지역·연도·모집 회차의 공식 자료인지 확인합니다. 기관 홈페이지나 키피오 내부 뉴스는 검수 원문으로 승인할 수 없습니다.
4. 확인할 원문 본문을 입력하고 직접 설명을 작성하거나 초안을 생성합니다. 각 설명에는 본문에 실제로 있는 근거 문장이 필요합니다.
5. 대상·서류·신청 순서·주의점을 원문과 대조합니다. 자동 초안이나 인용문 존재 검사만으로 정확성이 보장되지는 않습니다.
6. 초안을 저장하고 원문 대조 확인 항목을 선택한 뒤 승인합니다.
7. 승인 내용을 수정하려면 먼저 승인을 회수합니다.

정책의 조건이나 출처·기관·지역이 변경되면 기존 검수는 공개에 사용되지 않습니다. 이전 화면을 열어 둔 동안 정책이나 다른 검수가 바뀌면 저장이 거부되므로 다시 불러옵니다.

## 주소 점검 목록

점검 종류에서 공식 원문 확인 필요 또는 신청 주소가 기관 첫 화면인 자료를 골라 봅니다. 기관 첫 화면은 정부 주소여도 개별 공고 원문으로 인정하지 않습니다. 제목 검색은 선택한 점검 종류 안에서 적용됩니다.

수정할 주소를 입력하고 해당 사업·지역·연도·회차와 신청 방법을 대조한 뒤 주소 수정 버튼을 누릅니다. 한 번에 주소 하나를 저장하고 다시 불러온 자료를 확인합니다. 저장하지 않은 주소가 있으면 설명 생성·저장·승인이 차단됩니다.

주소를 수정하면 기존 설명 승인은 무효화됩니다. 이전 주소·비공개 설명은 관리자 전용 `policy_guidance_link_audit` 변경 기록에 보관합니다. 방문 접수 사업은 온라인 신청 주소를 억지로 만들어 넣지 말고 공식 공고의 접수 장소와 서류를 설명에 적습니다.

대표 초안 준비 도구는 `prepare-policy-review-pilot.mjs`, 비공개 저장 도구는 `store-policy-review-pilot.mjs`입니다. 저장 도구 기본 실행은 비교만 하며 `--apply`일 때에도 사람 승인 없이 비공개 초안만 저장합니다. 이미 있는 검수 자료와 변경된 정책은 덮어쓰지 않습니다.

전체 주소 대조 도구는 `triage-policy-source-backlog.mjs`이며 공식 보도자료 색인을 하루 동안 재사용합니다. 중단 시 이미 읽은 자료를 다시 읽지 않습니다. `verify-policy-backlog-candidates.mjs`는 같은 공식 주소를 한 번만 읽어 접속과 기존 문장 일치 여부를 확인합니다. 후보 제목·기관 일치는 최종 사실 검수나 공개 승인으로 취급하지 않습니다.

## 저장과 공개 범위

- `policy_guidance_reviews`: 초안, 원문 전체와 실제 검수자 번호를 보관하는 관리자 전용 저장 공간입니다. 공개·일반 로그인 사용자는 읽거나 쓰거나 저장 함수를 호출할 수 없습니다.
- 정책의 `policy_guidance`: 승인된 설명과 필요한 인용문, 출처·확인일·검수일만 공개합니다. 승인 전에는 상태 표시만 저장합니다.
- 정책과 검수 자료는 같은 저장 작업에서 함께 바뀝니다. 이전 수정 시각과 검수 번호를 대조해 동시 작업이 서로 덮어쓰지 못하게 합니다.
- 기존 자동 설명은 삭제하지 않으며 공개 화면과 검색 설명에 사용하지 않습니다.

## 자동 작성

새 자동 작성 작업은 원문이 충분한 자료의 초안만 저장합니다. 사람 승인 없이 공개하지 않습니다. 원문이 없는 자료는 확인 대기로 표시합니다. 시간 예산이 부족하면 나머지 자료를 보류합니다.

예전 `policy-insight-backfill` 경로는 인증을 유지한 채 생성 작업을 중단했습니다. 비용이 발생하는 기존 미검수 설명을 계속 만들지 않습니다.

## 출처 복구

`audit-policy-sources.mjs`로 주소를 조사하고 `prepare-policy-source-repairs.mjs`로 원본 연결 후보를 만듭니다. `apply-policy-source-repairs.mjs` 기본 실행은 비교표만 생성합니다. 운영 쓰기는 명시적 `--apply` 실행 때만 합니다.

적용 전 현재 정책의 이전 주소·수정 시각과 원본 뉴스의 실제 주소를 다시 확인합니다. 변경되거나 충돌한 항목은 보류합니다. 완료 항목의 이전 값과 적용 시각은 `applied-source-repairs.jsonl`에 누적됩니다. 자동 되돌리기 도구는 없습니다.

원본 언론사 기사 주소를 복구한 것은 공식 공고 확인이나 내용 검수 승인이 아닙니다. 기관 첫 화면 신청 주소는 실제 공고·신청 안내를 찾아 별도로 보완해야 합니다.

## 배포 확인

검수 저장 공간 관련 두 저장소 변경을 적용한 뒤 배포합니다. 홈 지도·지역 링크·뉴스·정책 상세 응답, 비로그인 관리자 접근 차단, 공개 저장소의 비공개 초안 조회 차단을 확인합니다.

검색 제출은 유효한 승인 설명을 기준으로 판단합니다. 심사 모드의 기존 정책 검색 제외 설정은 별도로 유지됩니다. 키워드 검사 통과나 글 개수만으로 애드센스 승인 가능 상태를 판단하지 않습니다.

## 자동 수집 주소와 처리 대기

자동 신청 주소는 기사 본문에 실제로 있는 기관 상세 주소만 사용합니다. 기관 첫 화면·인증 정보가 포함된 주소·본문에 없는 생성 주소는 자동 등록하지 않습니다. 본문에 주소가 있다는 이유로 같은 사업의 사람 검수를 승인하지 않습니다.

주소를 확인할 수 없는 후보는 사람의 대기 목록에 그대로 보존하고 다음 자동 처리에서 제외합니다. 사람 검수 또는 원문 보완 뒤 재분류하면 다시 검사합니다. 저장 직전 자료 내용이나 대기 상태가 달라지면 자동 등록을 중단합니다.

관리자 주소 수정은 해당 상세 페이지도 갱신합니다. 운영 저장소를 직접 교정하는 경우에는 상세 화면 저장이 최대 1시간 남을 수 있으므로 같은 경로의 갱신과 실제 화면 확인을 함께 진행합니다.
