# 정책뉴스 발행 후 운영 점검

## 반영 순서

`20261020000000_editorial_news_queue_status.sql`을 먼저 적용한 뒤 코드를 배포한다.
예약 함수는 기존 함수를 그대로 호출하며 같은 잠금 안에서 후보가 없는 이유를 반환한다.
기존 하루 공개 3편·새 후보 6건·재시도 조건은 변경하지 않는다.
적용 전에는 새 함수가 없어 발행이 실패하므로 코드부터 배포하지 않는다.

한복 기사 분류 보완은 `20261020001000_editorial_hanbok_region.sql`에 별도로 있다.
공식 원문의 전국 참여 프로그램 근거가 있는 한 편만 대상으로 하며, 현재 제목·분류·근거가
확인 당시와 다르면 수정하지 않는다. 본문·발행일·검수 기록은 바꾸지 않는다.

## 발행 0건과 실패 구분

관리자 검수 현황에서 현재 대기 상태와 최근 예약 실행 10건을 구분한다.
한도 도달, 처리 중, 후보 없음, 재시도 대기, 실행 시간·횟수 종료를 표시한다.
새 `editorial_news_runs`에는 건수·종료 이유만 저장하며 원문·초안·비밀값은 넣지 않는다.
기록 저장 실패는 응답의 `runRecorded=false`로 남긴다. 공개에 성공한 글을 실패로 되돌리지 않는다.
설정·예약 호출 등 실행 오류는 실패로 기록하지만, 중간에 처리된 글의 건수를 추측하지 않는다.
새 기록 이전의 과거 실행은 복원했다고 표시하지 않는다.

## 사진 검수

허가된 주제 사진을 선택한 뒤 운영 호스트의 원본·480·640 크기 파일을 동시에 확인한다.
각 요청은 5초 제한이며 다른 주소로 이동하지 않는다. 정상 응답과 웹피 이미지 형식을 확인한다.
한 파일이라도 확인되지 않으면 보류하고, 완료한 본문 검사 근거와 함께 사진 검사 결과를 보존한다.
네트워크 실패를 사진 없음으로 확정하지 않는다. 새 사진은 파일 배포 후 발행해야 한다.
이 응답 검사는 사진의 의미나 이용 허가를 새로 판정하는 절차가 아니다.
사진 주제와 허가는 등록 과정에서 별도로 확인해야 한다.

## 보류와 재검토

날짜 추정·작성 지시문 혼입에는 오류별 재작성 지침을 보충한다.
재작성 횟수와 원문·숫자·사실·충실도 검사는 유지하며 검사를 건너뛰지 않는다.
과거 보류 글을 수동 공개하거나 재시도 시각을 앞당기지 않는다.

공개 글은 마지막 확인 후 7일 경과 또는 요약의 일정 표현을 관리자 화면에 표시한다.
본문에만 있는 일정은 해당 글의 원문 재확인 화면에서 추가로 확인한다.
원문 재확인은 관리자만 가능하며 공식 원문을 다시 읽어 발행 당시 비교값과 대조한다.
원문이 같아도 날짜는 지나므로, 같다는 이유로 현재 신청·시행 가능하다고 표시하지 않는다.
제목 변경·접속 실패·과거 비교값 없음은 미확인으로 남긴다.
이 조회는 기사와 확인일을 변경하지 않는다. 실제 내용 수정은 원문 근거를 검토한 뒤 진행한다.

## 되돌리기

이전 코드를 먼저 배포하면 기존 예약 함수를 그대로 사용한다. 새 조회 함수와 실행 기록은 남겨도 기존 발행을 방해하지 않는다.
기록 테이블을 자동 삭제하지 않는다. 한복 분류를 되돌릴 때도 현재 분류가 이번 변경값과 같은지 확인하고
분류만 기존 `문화 / unclassified`로 복원한다. 이후 사람이 수정한 분류는 덮어쓰지 않는다.
