# 키피오 고객 의존형 SaaS 기능 플랜 — 2026-08-22

## 결론

키피오는 “정책 정보 사이트”가 아니라 **사장님 정책 마감 감시 시스템**으로 가야 한다. 고객이 매일 검색하지 않아도 키피오가 놓칠 정책을 대신 감시하고, 자격·마감·다음 행동을 알려줘야 월 4,900원 Basic 결제가 설득된다.

## 현재 목표

- 1차 수익: Basic 월 4,900원
- 30일 KPI
  - 사업자 프로필 저장 20명+
  - 알림 조건 생성 10건+
  - checkout started 3건+
  - Basic 결제 end-to-end 1건+
- 핵심 의존 행동: “내 가게 정보 저장 → 감시 조건 설정 → 마감 알림 수신 → 정책 상세 재방문”

## 제품 원칙

1. **검색보다 감시** — 사용자가 찾으러 오지 않아도 키피오가 알려준다.
2. **일반 추천보다 자격 판단** — “받을 수 있을 가능성”을 먼저 보여준다.
3. **콘텐츠보다 다음 행동** — 정책마다 “지금 해야 할 일”을 한 줄로 제시한다.
4. **유료 가치는 반복성** — 한 번 결제하고 끝이 아니라 매주/매월 의존하게 만든다.
5. **신뢰 우선** — 자격이 모호하면 “확인 필요”로 표시하고, 공식 출처 링크를 유지한다.

## 구현 로드맵

### Phase 1 — Activation: 유료 가치를 켜게 만들기

목표: Basic 결제 또는 가입 직후 사용자가 핵심 설정을 끝내게 한다.

완료/진행:
- `/pricing`을 정책 마감·자격 알림 SaaS 카피로 전환
- `/mypage/business` 저장 후 `/recommend`, `/alerts` 연결
- 홈/인기/도움말 CTA를 Basic pricing funnel로 통일
- `/alerts`에 **마감 감시 준비도 패널** 추가

다음 구현 후보:
1. `/mypage` 상단에 “내 정책 감시 상태” 요약 카드 추가
2. `/checkout/success`에서 바로 `사업자 프로필 → 알림 조건` 2단계 체크리스트로 이동
3. `/recommend?from=business-profile`에서 추천 결과가 0개여도 대체 조건 제안 표시

Acceptance:
- Free 사용자는 Basic CTA를 명확히 본다.
- Basic/Pro 사용자는 남은 설정 1개를 바로 해결할 수 있다.
- 테스트로 `free → pricing`, `basic → business/notifications`, `pro → kakao consent` 분기를 고정한다.

### Phase 2 — Retention: 매주 다시 오게 만들기

목표: “키피오가 내 정책을 감시 중”이라는 믿음을 만든다.

구현 후보:
1. 주간 정책 감시 리포트
   - 신규 매칭 정책 수
   - 마감 14일 이내 정책 수
   - 자격 확인 필요 정책 수
   - 이번 주 해야 할 일 1개
2. `/alerts`에서 “이번 주 감시 결과” read-only preview
3. 알림 발송이 없어도 “이번 주 조건에 맞는 신규 공고 없음” 상태를 보여줘 노쇼 불안을 줄임

Acceptance:
- 사용자는 알림이 없을 때도 서비스가 죽은 게 아니라 “감시 중”임을 확인한다.
- 7일 내 재방문 유도 CTA가 생긴다.

### Phase 3 — Conversion: 정책 상세에서 결제 이유 만들기

목표: 정책 상세를 보다가 “이걸 놓치면 손해”라는 순간에 Basic 결제로 연결한다.

구현 후보:
1. 정책 상세에 “내 조건 기준 자격 체크” Basic gate
2. 마감 D-14/D-7 정책에 “마감 알림 받기” CTA 강화
3. 비로그인/Free 사용자가 알림 등록 시 pricing Basic으로 연결
4. 관심 정책 저장 후 “이런 정책 새로 뜨면 알려드림” 메시지

Acceptance:
- 상세 페이지에서 Basic CTA 클릭 출처가 `from=policy-detail`로 추적된다.
- alert creation 전환율을 페이지별로 분리할 수 있다.

### Phase 4 — Trust: 고객이 돈 내도 불안하지 않게 만들기

목표: 자동 알림 SaaS의 신뢰도를 수치·근거로 보여준다.

구현 후보:
1. “마지막 감시 시각” 노출
2. 공식 출처/수집 시각/마감 확인 시각 표시
3. 알림 실패/반송 상태를 사용자에게 숨기지 않고 복구 CTA 제공
4. 관리자 화면에서 paid user alert health 모니터링

Acceptance:
- 유료 사용자의 알림 조건이 0개면 운영자가 볼 수 있다.
- 알림 발송 실패가 조용히 묻히지 않는다.

## 우선순위 TOP 5

1. `/mypage` 내 정책 감시 상태 카드
   - 이유: 로그인 후 가장 자주 보는 페이지에서 의존 루프를 고정한다.
2. `/checkout/success` 2단계 activation checklist
   - 이유: 결제 직후 설정 누락을 막는다.
3. 정책 상세 `마감 알림 받기 → Basic` funnel 정리
   - 이유: 결제 의도가 가장 높은 순간이다.
4. 주간 감시 리포트 preview
   - 이유: 알림 없는 주에도 서비스가 작동 중임을 증명한다.
5. Paid user alert health admin card
   - 이유: 유료 고객의 설정 누락/발송 실패를 운영자가 먼저 잡는다.

## 이번 구현분

이번 변경은 Phase 1의 “마감 감시 준비도 패널”이다.

- 위치: `/alerts`
- 기능:
  - Basic 이상 여부
  - 사업자 프로필 여부
  - 활성 알림 조건 수
  - 이메일 수신 경로
  - Pro일 때 카카오 알림톡 동의 여부
- 목적:
  - Free는 Basic으로 전환
  - Paid는 설정 누락을 해결
  - 고객이 “키피오가 내 정책을 감시 중”인지 한 화면에서 확인

## 안전선

- DB mutation 없음
- 결제/구독 상태 변경 없음
- 외부 발송 없음
- 모든 변경은 read-only 계산 + UI 표시
- production 배포는 별도 승인 후 진행
